# Диалоги и истории: руководство

Реализовано в `Assets/_Project/NPC/Dialogue`. Персонаж описывается одним C#-сценарием. `AnnaScenario`, `ProkhorScenario` и `AgafyevnaScenario` — готовые примеры; их префабы подключены в GameScene. Проверка агента ограничена компиляцией и консолью; gameplay проверяет пользователь.

## Как устроено выполнение

`NpcWantItem` передаёт попадание предмета в `NpcDialog`, обращение приходит через `IInteractable`. Компонент создаёт `ScenarioContext`, выбирает первое подходящее правило сценария и запускает `ScenarioRunner`. Исполнитель работает с явными объектами шагов и условий, без обязательных восьми реакций и без универсального флага «NPC получил нужный предмет».

`DialoguePresenter` управляет общим окном, камерой и вводом. Все реплики готовых сценариев используют обычный диалог (`SpeechMode.Dialogue`), включая отказы на предметы и повторные обращения. Защищённые катсцены сохраняют прежнее поведение. `WorldText` остаётся доступен в runtime для текста над NPC. `GameSequencer.Story` хранит состояние текущей попытки. Next try перезагружает сцену и создаёт чистое состояние.

## Собрать NPC

1. Создать обычный C#-класс — наследник `NpcScenario` с уникальным `Id`, массивом `Rules` и массивом `Endings`.
2. Создать тонкий Unity-компонент — наследник `NpcDialog`, возвращающий этот сценарий из `CreateScenario()`; имя файла совпадает с именем компонента.
3. Удобнее скопировать префаб AnnaNpc или ProkhorNpc, заменить компонент конкретного NPC и назначить имя, камеру, WorldText и PlayerPosition. Сохранить Rigidbody, триггер, NpcWantItem и TAnimSoundWriter. Триггеру нужен слой, используемый существующими взаимодействиями.
4. В `feedbacks` назначить только используемые сценарием пары `id` / `MMF_Player`. Списки эффектов MMF_Player остаются для ручной настройки; у Агафьевны по запросу настроена только реакция на таблетки с приближением и дрожанием камеры. В `cameras` можно назначить дополнительные пары `id` / `CinemachineCamera`.
5. Разместить NPC во второй игровой зоне. В сцене нужны GameSequencer и DialoguePresenter. Один сюжетный Id принадлежит одному NPC; дополнительные копии с тем же Id не являются отдельными персонажами.

Минимальный пример:

```csharp
using DialogueSystem;

public sealed class VisitorScenario : NpcScenario
{
    public override string Id => "visitor";

    public override ScenarioRule[] Rules { get; } = new[]
    {
        new ScenarioRule(ScenarioEvent.Interact, new Always(),
            new Say(SpeechMode.Dialogue, "Добрый вечер."))
    };

    public override EndingRule[] Endings { get; } = new[]
    {
        new EndingRule(new Always(), "Посетитель дождался утра.")
    };
}

// В отдельном файле VisitorNpcDialog.cs:
public sealed class VisitorNpcDialog : NpcDialog
{
    protected override NpcScenario CreateScenario() => new VisitorScenario();
}
```

## Правила и условия

`ScenarioRule(trigger, condition, steps, itemDisposition, onReceipt)` описывает одну реакцию. Триггеры: `Interact` и `ItemHit`. Порядок объявления важен: выбирается первое совпадение только среди правил текущего события. Общее правило `Always` ставится последним. Отсутствие подходящего правила означает игнорирование события.

| Условие | Значение |
| --- | --- |
| `Always()` | Всегда подходит |
| `FactIs<T>(key, value)` | Общий сюжетный факт равен значению |
| `ItemIs(ids...)` | Тип попавшего предмета входит в список |
| `DuringIntroduction()` | Попадание произошло во время вступления |
| `InDialogue()` | На момент события открыт разговор именно с этим NPC |
| `All(conditions...)` | Выполнены все условия |
| `Any(conditions...)` | Выполнено хотя бы одно |
| `Not(condition)` | Условие не выполнено |

Контекст содержит NPC, общий StoryState, предмет и снимки состояния разговора на момент события. Условия должны только читать состояние. Фазы вступления задаются явно шагами `SetIntroduction(true/false)`; знакомство — обычным сюжетным фактом. Анна отмечается встреченной в начале знакомства; Прохор продвигает ProkhorVisits в начале каждого вступительного блока, поэтому прерванный блок не повторяется.

## Шаги

| Шаг | Назначение |
| --- | --- |
| `Sequence(steps...)` | Последовательно выполнить шаги |
| `Say(mode, lines...)` | Показать реплики владельца сценария |
| `Say(actorId, mode, cameraId, lines...)` | Реплики другого говорящего и выбранный ракурс |
| `Branch(condition, yes, no)` | Проверить условие при достижении шага и выполнить выбранное продолжение |
| `SetFact<T>(key, value)` | Записать общий сюжетный факт |
| `SetIntroduction(value)` | Отметить или закончить вступительную часть |
| `PlayFeedback(id)` | Запустить MMF_Player из привязок владельца сценария |
| `ProtectedSequence(steps...)` | Выполнить последовательность с запретом выброса, выбора и приёма предметов |
| `EndDialogue()` | Закончить сценарное выполнение и закрыть принадлежащий ему разговор |

Последний шаг не обязан быть EndDialogue: исчерпание последовательности тоже завершает выполнение и закрывает окно. Пустая Sequence корректно завершается. EndDialogue прекращает и оставшиеся шаги текущего выполнения.

`SpeechMode.Dialogue` открывает полноценный разговор, `World` показывает текст над NPC, `Current` выбирает окно, если на момент события открыт разговор с владельцем сценария, иначе текст над NPC. Для каждой реплики используется озвучивание печати её текущего говорящего. Над NPC цепочка продвигается автоматически; полноценный разговор использует E, пробел или щелчок. ESC его не закрывает.

Камера без id берётся из основного поля говорящего. Именованная камера ищется в `cameras` этого же говорящего. Смена говорящего/камеры внутри одной сессии не переносит игрока повторно. Точка игрока принадлежит инициатору разговора.

## Предметы: комментарий, принятие и последствия

По умолчанию правило использует `ItemDisposition.Keep`: предмет остаётся доступен игроку. Так работают отказы и перенаправления Анны и Прохора.

`ItemDisposition.Consume` убирает попавший экземпляр из мира. Принимается только активный выброшенный предмет без владельца. Это не запрещает NPC принимать следующие предметы: такое ограничение автор при необходимости задаёт условием на факт.

`OnReceipt` содержит изменения фактов, которые должны произойти при передаче, до начала реплик. Сначала проверяются шаги, говорящие, ссылки и ключи фактов, затем изменения применяются к копии состояния и публикуются вместе. Ошибка подготовки не расходует предмет и не заменяет текущую реакцию. Ошибка уже начавшегося шага завершает разговор с сообщением в консоли; выполненные последствия не откатываются.

Пример правила приёма таблеток (полная реализация — AgafyevnaScenario):

```csharp
new ScenarioRule(
    ScenarioEvent.ItemHit,
    new ItemIs(ItemId.Pills),
    new Say(SpeechMode.Dialogue, "Хоть бы до утра. Хоть бы до свету дожить!"),
    ItemDisposition.Consume,
    new SetFact<LizaHelp>(StoryFacts.LizaTreatment, LizaHelp.Pills))
```

Для спирта и стетоскопа задаются другие правила с соответствующим значением. До таблеток повторная передача заменяет `LizaTreatment`: после спирта или стетоскопа можно передать таблетки и спасти Лизу. Таблетки имеют приоритет: после них Агафьевна отвечает на спирт и стетоскоп «Мне больше это не нужно.», оставляет предмет в мире и сохраняет `LizaHelp.Pills` без запуска feedback принятия. Факт вида помощи не означает, что Лиза уже умерла или выздоровела.

Текущие ItemId: Vase=0, Typewriter=1, Stethoscope=2, Pills=3, Alcohol=4, Calculator=5, Polaroid=6, Pencil=7, Abacus=8, Glasses=9. Старые значения сохранены. Предметы имеют префабы на основе базового Item с визуалом из примитивов и размещены в зоне сбора.

## Общие факты и итоги

Объявлять ключ нужно один раз, например в отдельном статическом классе сюжета:

```csharp
public static readonly StoryKey<bool> GrandpaMet =
    new StoryKey<bool>("grandpa.met", false);
```

Один и тот же экземпляр ключа используется всеми сценариями. Одинаковый строковый Id у двух разных экземпляров ключа — ошибка, даже если их тип совпадает. Начальное значение задаётся явно. Доступ к фактам: `context.State.Get(key)` и `context.State.Set(key, value)`; в готовых сценариях обычно достаточно FactIs и SetFact.

`Endings` тоже проверяются сверху вниз. Последнее правило Always обязательно для истории без взаимодействий. Пустой текст итога исключает NPC из общего экрана без дополнительного отступа. Условия итогов только читают состояние, поэтому результат не зависит от порядка NPC на экране итогов. GameSequencer отменяет незавершённые реакции перед сбором историй.

У Анны и Прохора таблетки дают выздоровление Лизы, спирт, стетоскоп и отсутствие помощи — смерть в конце. Пока идёт игра, реплики Анны описывают текущее лечение, а не будущий исход.

## Условие, важное именно в момент передачи

Branch проверяет факты, когда исполнитель до него дошёл. Если важен порядок действий, как при калькуляторе Ильи, выбрать ветку нужно условием правила ItemHit и сразу записать выбранный вариант в OnReceipt.

У Ильи это реализовано двумя правилами ItemHit. Первое требует IlyaCalculatorGiven=false и InnokentyRequestReached=true: принимает калькулятор и запускает ответ вместе со сценой письма. Второе принимает калькулятор без сцены. Оба сразу записывают IlyaCalculatorGiven=true в OnReceipt. После передачи новые разговоры с Дедом уже не меняют выбранный вариант.

IlyaCalculatorGiven запрещает повторное принятие и повторный запуск. LetterRead записывается после последней реплики совместной сцены и определяет хороший исход Иннокентия. InnokentyRequestReached означает достижение просьбы на пятом обращении, а не просто первое знакомство.

## Диалог нескольких персонажей

```csharp
new ProtectedSequence(
    new Say("innokenty", SpeechMode.Dialogue, null,
        "Эй. Грамотный! Слышь, что ли. Поди сюда."),
    new Say("ilya", SpeechMode.Dialogue, null,
        "Я всю ночь сводил. Я спать хочу."),
    new Say("innokenty", SpeechMode.Dialogue, "letterCloseup",
        "Только вслух не надо.",
        "Ты про себя прочти и мне скажи. Одним словом."),
    new Say("ilya", SpeechMode.Dialogue, null, "Живой."))
```

Идентификаторы должны соответствовать Id размещённых NPC; `letterCloseup` в примере — привязка камеры у Иннокентия. Все участвующие NPC и камеры требуются уже при подготовке реакции, включая альтернативные ветки Branch. После блока восстанавливается прежний режим приёма предметов; после окончания всего сценария возвращается игровая камера. Реальные Илья и Иннокентий уже добавлены; их сцена использует отдельные привязки Letter01_Call–Letter15_Fool, перечисленные ниже.

## Прерывания и расширение

Новая обычная реакция заменяет предыдущую без очереди. Незавершённые шаги выбрасываются; поздний callback старого запуска игнорируется. Уже выполненные SetFact и принятие предмета сохраняются. Попадание другому NPC во время занятого окна игнорируется без расхода предмета. В ProtectedSequence игнорируются и уже летящие предметы.

Своё условие наследуется от ScenarioCondition и реализует Matches(context); Validate(context) проверяет необходимые настройки. Проверка не должна менять сюжет.

Свой шаг наследуется от ScenarioStep. Validate выполняется до принятия предмета, Execute(runner) — при достижении шага. Синхронному шагу достаточно выполнить действие и вернуться. Для задержки вызывается `Action resume = runner.Await()`, затем resume передаётся источнику завершения. Повторное завершение или callback отменённого запуска безопасно игнорируется. Для последовательностей используется runner.Push(step), текущий контекст доступен через runner.Context. Настройки нового шага следует хранить явно в его полях/свойствах, а не прятать в замыкании.

OnReceipt предназначен только для записи фактов через FactChange; внешние эффекты выполняются обычными шагами после передачи. Для остановки своего внешнего эффекта шаг регистрирует runner.OnEnd(cleanup); обработчик вызывается при нормальном завершении, отмене и замене реакции. Защита callback предотвращает продолжение старого сценария.

## Анна и Прохор в проекте

- `NPC/AnnaNpc.prefab` заменяет демонстрационную Аню с вазой; `NPC/ProkhorNpc.prefab` — демонстрационного Илью. GUID префабов и компонентов сохранены, существующие камеры и точки игрока перенесены.
- Анна: первое вступление → просьба; ранний неверный предмет → «К чему это?» → просьба; неверный предмет позже → отказ и конец. Медицинский предмет после знакомства → «Не мне. Отдай Агафьевне» и конец. До знакомства — обычный диалог «Тише ты. Разбудишь её».
- После помощи у Агафьевны повторное обращение к Анне открывает обычный диалог с соответствующей репликой из AnnaScenario. До помощи повторяется просьба.
- Прохор: первое обращение — «Стоишь — стой… Отойди от неё!» и закрытие разговора; второе — «Я тебе не рад… Восьмой — лишний» и просьба «Я два дня как с дороги…»; с третьего повторяется только просьба. ProkhorVisits продвигается в начале каждого блока, поэтому прерванный блок не повторяется. Неверный предмет → «Убери» и конец; медицинский после начала знакомства → «Это не мне. Отдай старухе» и конец. Предметы не продвигают счётчик: до знакомства — обычный диалог «Убери», знакомство ещё доступно; после первого блока следующий разговор начинает второй.
- Старые MMF_Player сохранены как именованные привязки; неиспользуемые группы не обязательны для новых NPC. Для Анны и Прохора дополнительные эффекты не настроены.

## Барбос

`BarbosScenario` / `BarbosNpcDialog` / `NPC/BarbosNpc.prefab` подключены в GameScene. Барбос собран из примитивов и стоит в четырёх метрах от Анны по +X. Каждое обращение открывает только «ГАВ!», после продолжения реплики разговор закрывается. Реакций на предметы нет. На общем экране итогов Барбос не появляется. Озвучка и feedback-эффекты не назначены.

## Путь к графу

Редактор графов сможет создавать те же классы шагов и условий. Понадобятся сериализация, устойчивые Id узлов, редакторы параметров и проверка переходов. Runtime, представление и сюжетные факты можно использовать повторно. Автоматического преобразования произвольного пользовательского C# в граф нет.

## Агафьевна и медицинские предметы

`AgafyevnaScenario` / `AgafyevnaNpcDialog` / `NPC/AgafyevnaNpc.prefab` подключены в GameScene. Агафьевна стоит между Прохором и Анной, в пяти метрах от Анны по X. Модель — капсула с головным платком из сферы. Камера, точка игрока, триггер и текст над головой повторяют устройство остальных NPC.

Три отдельных обращения: «Не лезь» и «Ходит тут. Ходит, а толку нет» → выход; «Ты кто таков? Не из наших. И не прохожий — прохожие так не стоят» и «…» → выход; «Ну и стой. Мне-то что» и «…» → выход. С четвёртого обращения без медицинской помощи повторяется только просьба «Не дотянет до свету…»; после помощи остаются реплики по текущему лечению. `AgafyevnaVisits` продвигается в начале каждого вступления, поэтому прерванный блок не повторяется. Передачи предметов не меняют счётчик.

До знакомства любой предмет открывает обычный диалог с отказом без принятия. Неверный предмет вызывает «Убери от меня эту дребедень!» → выход; он прерывает текущие реплики, но не пропускает оставшиеся вступления. Следующее обращение выбирается по счётчику. Ранний медицинский предмет принимается с фразой «А? Чего ты мне тут суёшь?!», затем идут реплики конкретного предмета. После знакомства медицинский предмет принимается и открывает полноценный диалог даже вне текущего разговора. Повторная передача меняет лечение только до таблеток; после них спирт и стетоскоп больше не принимаются. Повторные таблетки принимаются как прежде. Сама смерть или выздоровление остаются событием конца попытки.

Стетоскоп собран из капсул и цилиндра, таблетки — блистер с шестью сферами, спирт — цилиндрическая бутылка с крышкой и крестом. Варианты базового Item наследуют подбор, физику и работу в инвентаре; каждый использует один простой BoxCollider. Базовый визуал выключен, Item.Visual ссылается на MedicalVisual. Стоимость не назначена. Исходные ваза и машинка сохранены в зоне сбора; новые предметы стоят рядом в InteractionItemsDemo.

У реакции PillsReceived настроены MMF_CameraZoom и MMF_CameraShake. Изолированный AgafyevnaSniffChannel связывает их только с камерой Агафьевны; AgafyevnaSniffNoise задаёт небольшое покачивание. Приближение — до 80% исходного FOV, переход 0,12 с, удержание 0,65 с; дрожание длится 0,65 с. Остальные списки MMF_Player оставлены пустыми. Эти значения можно менять в префабе; визуальный эффект агент не проверял.

Для такого случая у Say есть необязательное свойство StartFeedback:

```csharp
new Say(SpeechMode.Dialogue, "Плесенью пахнет", "Хлебной")
{
    StartFeedback = "PillsReceived"
}
```

Этот feedback запускается после открытия окна и включения камеры. При окончании или замене сценария исполнитель останавливает его и восстанавливает исходные значения, пока камера ещё активна. Отдельный PlayFeedback по-прежнему запускается немедленно в своей позиции последовательности.

Реплики по предметам перенесены с разбиением по авторским `||`. Итоговые тексты самой Агафьевны написаны кратко по исходам схемы и находятся в Endings её сценария.

## Егор и полароид

`EgorScenario` / `EgorNpcDialog` / `NPC/EgorNpc.prefab` подключены в GameScene. Егор стоит рядом с Барбосом, в точке (260.8, 0, 6.5). Полароид и карандаш размещены в InteractionItemsDemo; их ItemId добавлены в конец enum без изменения прежних значений.

У Егора три отдельных обращения: «Сядь, чего стоишь. Место есть» → «Утром обоз…» и рассказ о карточке для матери → «Ты не думай, я не боюсь…». Первые два заканчиваются закрытием разговора. EgorScenario.Visits продвигается в начале каждого блока, поэтому прерванный блок не повторяется. После третьего блока наличие полароида в любом слоте запускает Photo; с четвёртого обращения проверка выполняется сразу, а без камеры повторяется третий блок. Попадание полароида на любом этапе пропускает оставшееся интро, возвращает тот же экземпляр через Pickup и выбирает его активным, затем открывает ветку Photo. После сделанного фото повторные обращения дают «Спасибо». Повторно брошенная камера также возвращается, но нового снимка не требуется. Карандаш вызывает свою реплику, прочие предметы — «А толку-то?»; оба отказа оставляют предмет в мире, не продвигают интро и не запрещают последующее фото.

Ветка Photo — ProtectedSequence: выброс, выбор слота и новые попадания заблокированы. PreparePolaroid выбирает камеру, Say показывает «Что это?», TakeEgorPhoto показывает «Не двигаться? Хорошо» и ждёт Q. Необязательный аргумент waitForAction у DialoguePresenter.TryShow позволяет допечатать текущую реплику обычным вводом, но запрещает пройти её без сценарного действия. Сама съёмка не требует дополнительного E. После передачи карточки следующие реплики продвигаются как обычно.

На Q запускается пустой MMF_Player `Feedbacks/PhotoTaken`: сюда вручную добавляются белая вспышка и звук. Через секунду создаётся PhotoCard, летит к PhotoTarget за 0.5 с и уменьшается до нуля за 0.2 с через DOTween. Карточка не является подбираемым Item; на ней условный портрет из примитивов. Исход хранится в EgorScenario.Photographed после завершения передачи. Карандаш не закрепляет плохую концовку: единственное условие спокойного исхода — переданное фото. При отмене сценария coroutine, tween, карточка и feedback очищаются.

В диалоге полароид, как и любой активный предмет, крепится к `Player/DialogueItemMount` и отображается основной камерой с обычной глубиной. Карточка появляется в `PolaroidVisual/PhotoOrigin`, назначенном в компоненте `Polaroid` на префабе камеры. Точку выхода можно двигать в инспекторе; задержки и длительность передачи прежние.

## Илья и Иннокентий

`IlyaScenario` / `IlyaNpcDialog` / `NPC/IlyaNpc.prefab` и `InnokentyScenario` / `InnokentyNpcDialog` / `NPC/InnokentyNpc.prefab` подключены в GameScene. Персонажи собраны из примитивов и стоят на шесть метров по -Z от ряда Анны: Илья (251.8, 0, 0.5), Иннокентий (255.3, 0, 0.5). Calculator, Abacus и Glasses — новые варианты Item с одним BoxCollider и визуалом из примитивов; стоят в InteractionItemsDemo в ряду Z=1.8. Карандаш и спирт используются существующие.

У Ильи три отдельных обращения: «Сорок один…» → «Я так с вечера…» → «Мне к утру ведомость…» и просьба «Я не хочу на фронт…». После каждого блока разговор закрывается; с четвёртого обращения повторяется только просьба. IlyaVisits продвигается в начале каждого блока, поэтому прерванный блок не повторяется. Неподходящий предмет до третьего блока сразу вызывает реакцию, а следующее обращение начинает третий блок с просьбой; после третьего блока предметы не возвращают интро. Карандаш, счёты и прочие отказы оставляют предмет в мире и не меняют исход. Калькулятор расходуется один раз на любом этапе и сразу задаёт «Илья сдал». Без калькулятора и без таблеток у Агафьевны — «Илья сдал в тишине»; без калькулятора при спасённой Лизе — «Илья не сдал». Эти условия действуют и без взаимодействий с Ильёй. Повторное обращение после калькулятора: «Теперь всё сходится.». Новый калькулятор уже не принимается; на счёты после калькулятора Илья отвечает «Мне это больше не нужно.» и оставляет их в мире. Сдача в тишине не запускает сцену письма.

У Иннокентия пять отдельных обращений: «...» → «...» → «Ну?» → «Отстань христа ради, я никому ничего не должен» → блок про письмо и просьба. После пятого просьба не повторяется: только «Отстань…» и выход. Только спирт или очки до просьбы вызывают реакцию с пропуском оставшегося интро: следующее обращение начинает пятый блок. Прочие предметы вызывают «Убери» без изменения счётчика обращений. Если пятый блок прерван до просьбы, спирт или очки снова делают его доступным. Спирт расходуется, очки и прочие предметы остаются. Они не блокируют будущую сцену письма и не отменяют её результат.

Схема общей истории: дойти до просьбы Иннокентия → передать Илье калькулятор → ответ на калькулятор → совместное чтение письма → «Илья сдал» и «Дед не спился». Если калькулятор передан раньше просьбы, Илья сдаёт, но позднее знакомство с дедом не запускает сцену. Без завершённой сцены, в том числе без взаимодействий, итог деда — «Дед спился». Хороший исход записывается после последней реплики «Дурак…». Повторное обращение после сцены: «Живой. Слышал? Живой».

Ответ на калькулятор в ветке письма и сама сцена защищены `ProtectedSequence`: Q, смена слота и новые попадания не прерывают сцену. Реплики продвигаются обычным E / пробелом / щелчком. Ремарки о доставании письма, чтении и долгом молчании пока представлены реквизитом, репликами «...» и сменой камер; анимаций и временных пауз нет. Общий runtime не изменён.

### Настройка камер катсцены в инспекторе

Камеры созданы дочерними объектами `LetterCameras` в префабе соответствующего говорящего.
