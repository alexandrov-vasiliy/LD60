# Взаимодействие и предметы

Статус: реализовано; Player, базовый Item и варианты Vase/Typewriter настроены через Unity Pipeline.

## Реализация и проверка

- `Assets/_Project/Player/Player.prefab`: инвентарь, поиск цели, крепление, Overlay-камера и подсказка E. Движение и шаги сохранены.
- `Assets/_Project/Items/Item.prefab`: Rigidbody, компонент Item, PickupInteractable, примитив с коллайдером. Vase и Typewriter — варианты этого префаба; enum `ItemId` содержит только эти два значения.
- В SampleScene размещены четыре предмета для проверки полного инвентаря. Слои: Interactable, HeldItem, Player.
- Управление: E — взаимодействие, Q — выброс, колесо — следующий/предыдущий слот с переходом через границу.
- Настройки дальности/радиуса и маски targetLayers (Interactable) — на PlayerInteractor; вместимости и выброса — на PlayerInventory; длительности подлёта — на HeldItemPresenter; offsets и масштаба — на Item.
- API PlayerInventory: `Slots` (только чтение), `ActiveIndex`, `ActiveItem`, `Contains(ItemId)`, `Pickup(Item)`, `SelectSlot(int)`, `DropActive()`, `TryExtract(Item)`. Извлечение возвращает bool; переданный экземпляр освобождается, становится активным в мире в текущей точке выброса с физикой, без импульса. Вызывающий код может сразу переместить или уничтожить его.
- Проверки агента ограничены компиляцией и консолью Unity. Геймплей проверяет пользователь; вход в Play Mode, симуляция ввода и игровые самопроверки выполняются только по его прямому запросу.

## Согласованное поведение

- Поиск цели: SphereCast из центра камеры, настраиваемые дальность и радиус (начальные значения 2,5 м и 0,08 м). Проверяется только ближайший коллайдер в маске Interactable; взаимодействие выполняется при наличии доступного IInteractable. Коллайдеры на других слоях игнорируются, включая стены.
- При наведении на доступную цель появляется простая подсказка E.
- Инвентарь содержит настраиваемое число слотов, по умолчанию три. Один экземпляр занимает один слот; стакинга нет. Enum ID обозначает тип предмета.
- Подбор занимает первый свободный слот и переключает выбор на него. Предмет подлетает к руке с DOTween-анимацией.
- Если свободных слотов нет, предмет активного слота выбрасывается, а подобранный занимает его место.
- Q выбрасывает активный предмет в мир с физикой.
- В диалоге доступны Q и колесо; движение, обзор и подбор заблокированы. Выброс идёт от `playerDropOrigin` (Head игрока) по направлению игрока, независимо от постановочной камеры; вне диалога используется прежний `dropOrigin`. Перед открытием диалога игрок переносится в `PlayerPosition` конкретного NPC. Пауза, катсцена и итоги по-прежнему блокируют инвентарь.
- Выброс всегда освобождает слот, возвращает предмету физику Unity и даёт небольшой настраиваемый толчок вперёд. Проверки свободного места, поиска безопасной позиции и отмены выброса нет. Это же правило действует при замене предмета в полном инвентаре.
- Колесо переключает все слоты по кругу, включая пустые. В руке виден только активный предмет.
- Вторая камера рисует предмет в руке поверх мира. На компоненте предмета настраиваются локальные position/rotation offsets и scale относительно крепления у камеры; нейтральные значения — нулевые offsets и единичный scale.
- Базовый префаб предмета и его варианты; настройки и дополнительная логика находятся на компонентах, без ScriptableObject-конфигов. Предпочтение композиции компонентов.
- Общий интерфейс взаимодействия должен допускать будущие цели, включая NPC. Предмет — частный случай цели.
- Общий контракт содержит проверку доступности и выполнение взаимодействия. Подсказка E скрыта для недоступных целей.
- Подбор сразу закрепляет владение предметом за слотом. При переключении, выбросе или новом подборе во время анимации текущий подлёт завершается немедленно, затем выполняется новая команда.
- Подлёт отображается в мире с обычным перекрытием препятствиями; при достижении руки предмет переходит на камеру предметов. Начальная настраиваемая длительность — 0,2 секунды.
- Публичное API: просмотр слотов и активного предмета, проверка типа, извлечение конкретного предмета без выброса. Извлечение освобождает слот и передаёт объект вызывающему коду для дальнейшего размещения или уничтожения. Правила передачи NPC описаны в `dialogue-rework.md`.

## Интеграция

Существуют Input System action Interact (E), DOTween и URP Forward+ с поддержкой Base/Overlay camera stacking. Изменения потребуются в компонентах взаимодействия/инвентаря/предмета, префабе игрока, привязках ввода, слоях, UI, базовом префабе и вариантах предметов, демонстрационной сцене и проверках новых правил. Передвижение и отклики шагов сохраняются.

## Предлагаемое разделение компонентов

- `IInteractable`: доступность и выполнение действия с контекстом взаимодействующего игрока.
- `PlayerInteractor`: поиск доступной цели и вызов взаимодействия по E.
- `PlayerInventory`: слоты, активный индекс, подбор, переключение, выброс и публичное API извлечения. Наружу не отдаёт изменяемое хранилище слотов.
- `Item`: enum типа и настройки экземпляра на префабе.
- `PickupInteractable`: компонент, связывающий общий контракт взаимодействия с подбором предмета.
- `HeldItemPresenter`: крепление у камеры, анимация, offsets, видимость и переход между отображением в мире и в руке.
- `InteractionPrompt`: простое отображение E по текущей доступной цели.

Разделение предварительное: минимальные детали реализации уточняются по существующему коду, без базовой иерархии классов предметов и системы событий для несуществующих потребителей.

## Сознательное ограничение

При выбросе рядом со стеной возможно начальное пересечение коллайдеров и резкое выталкивание физикой Unity. По решению пользователя отдельную проверку добавлять только при обнаружении проблем в игре; сейчас она не входит в объём реализации.
